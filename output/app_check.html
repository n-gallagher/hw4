Check 2: Dynamic search-result cards after a category question

  1. Started on the Home page, which has no product grid: 0 product cards and no results section before the question.
  2. Asked the concierge: "What crewnecks do you have?"
  3. Clicked one of the new cards (Champion Reverse Weave Crewneck).
Tools the agent called: search_products(category='Crewnecks') → show_products([6 crewneck ids]). The API returned these as structured products[], and the front end rendered them as cards. Database check: 29 products are crewnecks; all 6 cards are in that set, and every card's $58 price matches the DB.
What this proves: A category question makes the agent search the catalogue and return structured product matches that the website turns into real product cards on the page (they weren't there before), and those cards still open the full single-item page.

Check 3: Problem 9 feature, the agent adds to your bag (via the Bulldog concierge)

Problem 9 added four improvements (bag drawer, "Shop my size", price & stock fact-checker, agent add-to-bag). This check tests "Agent can add to your bag" (the new add_to_bag tool). It also shows the bag drawer and the fact-checker badge working in the same flow.

  1. Bag empty (no badge on the bag icon). On the Products page, asked the concierge: "Please add a medium Baseball Left Chest Crewneck to my bag."
Tool the agent called: add_to_bag(product='baseball-left-chest-crewneck', size='M', quantity=1). The server checked live stock (M = 5, 0 already in the bag) before adding, and returned bag_additions, which the website put in the bag. Price $58 and "5 left" match the database.
What this proves: The Problem 9 "agent adds to your bag" feature works end to end in the live app. A plain-English request becomes a stock-checked bag addition, the bag updates and opens, and the numbers in the reply were verified against the database.

⚠ Needs revisiting (found during this test)

  1. FIXED & RE-TESTED Usage log lost the list of tools called. In agent.log_usage, the usage summary's numeric tool_calls count overwrote the list of tool calls, so the audit log showed 3 instead of which tools ran. Fixed by storing the list as tools_called; Check 1 was re-run and the log now shows each call.
  2. FIXED & RE-TESTED Fact-checker skipped size-labelled counts. The first run's badge said "1 stock count verified" although the reply also listed "S (15), L (25), XXL (25)". Stock counts written as S (15) / M: 5 weren't recognized. Added that pattern (a test with a wrong "L (99)" is now caught); the re-run shows "4 stock counts verified". The graded question set still passes 8/8 afterwards.
  3. FIXED & RE-TESTED Agent nudged "check out soon", but checkout isn't open yet (the bag shows "Checkout (coming soon)"). Added a prompt rule: never say "check out / buy now"; for low stock, suggest keeping it in the bag and note items aren't reserved until checkout opens. Re-test reply: "Only 5 medium units are left in stock, so it's worth keeping an eye on. Items aren't reserved until checkout opens."
  4. FIXED & RE-TESTED Category answers showed only the first 6 of 29 with no way to see the rest. The results section now adds a "See all 29 crewnecks →" link to /products?category=Crewnecks whenever all matches share a category (count read live from the catalogue).
  5. FIXED & RE-TESTED Bag adds reused the "From your chat" banner (title became "PLEASE ADD A MEDIUM…", Screenshot 3b). Replies that only add to the bag no longer replace the banner; the bag drawer shows the item, and the chat button reads "View your bag →".
  6. FIXED & RE-TESTED Create-account form overflow (reported while reviewing the site): the side-by-side First/Last name fields didn't shrink, so the Last name box spilled past the card's right edge. Fixed in CSS; every input now ends 33 px inside the card, aligned with Email and Password.
  7. NOTE The fact-checker can raise a false alarm on unusual phrasings like "2 in M-L range"; the effect is only an extra retry, never a wrong answer to the shopper.
